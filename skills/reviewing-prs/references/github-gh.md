# GitHub (`gh`) Adapter for Pull Request Reviews

This reference defines the GitHub CLI (`gh`) and REST API commands for [SKILL.md](../SKILL.md). Complete the `Forge Selection Gate` and `Reviewer Identity Gate` in `references/forge-cli.md` before staging or publishing any remote review.

---

## Step 1: Identity, PR Context, Threads, Issues & CI Queries

Run these read-only queries to inspect the active reviewer account, pull request metadata, discussion history, linked issues, and CI checks:

```bash
# Query active GitHub account login (never echo GH_TOKEN or token values)
gh api user -q .login

# Fetch PR metadata including nested author.login, commits, headRefOid, and linked issues
gh pr view <id> --json number,title,body,baseRefName,headRefName,headRefOid,url,closingIssuesReferences,author,commits

# View general issue-level conversation comments (excludes inline diff review threads)
gh pr view <id> --comments

# Fetch prior review summary bodies, states, and reviewed commits
gh api repos/{owner}/{repo}/pulls/<pr>/reviews --jq '.[] | {user: .user.login, state, commit_id, body}'

# Fetch existing inline code review threads (required for Delta Reviews)
gh api repos/{owner}/{repo}/pulls/<pr>/comments --jq '.[] | {id, path, line: (.line // .original_line), user: .user.login, body}'

# Inspect linked issue requirements and acceptance criteria
gh issue view <num> --json title,body,labels

# Inspect CI check statuses and failed workflow run logs
gh pr checks <id>
gh run view <run-id> --log-failed
```

- **Fork Repository Override**: On forked repositories, `gh` targets `upstream` over `origin` by default. When reviewing a pull request opened against the fork itself, pass `-R OWNER/REPO` explicitly and verify target resolution with `gh repo view --json nameWithOwner`.
- **Reviewer Identity Gate (`gh`)**: Before staging (`Mode A`) or publishing (`Mode B`) a review to GitHub, compare `gh api user -q .login` against `pr.author.login` case-insensitively. If they match, abort immediately before calling `POST repos/{owner}/{repo}/pulls/<pr>/reviews`:
  `Active gh account '<gh_user>' matches PR author '<pr.author.login>'. Switch to a reviewer account before posting a review to GitHub.`

## Step 2: Diff Retrieval & Hunk Line Bounds

Retrieve changed file paths and the unified pull request diff:

```bash
# List changed files
gh pr diff <id> --name-only

# Fetch full unified diff
gh pr diff <id>
```

Verify inline comment line numbers against active diff hunks:

1. GitHub requires every inline comment target line to exist inside an active diff hunk on the selected side.
2. When inspecting a file with `nl -ba <file>`, cross-reference line numbers against `gh pr diff <id> -- <file>` and inspect each hunk header `@@ -os,oc +ns,nc @@`:
   - **Additions, modifications, or unchanged context (`"side": "RIGHT"`)**: Target `"line"` must fall within `[ns, ns + nc - 1]`.
   - **Deletions (`"side": "LEFT"`)**: Target `"line"` must fall within `[os, os + oc - 1]`.
3. If a finding targets code outside every diff hunk in that file, displace it into `### Comments on Lines Outside Diff` inside the summary `body`.

---

## Step 3: Local Checkout

After inspecting diffs to `Makefile`, `package.json` scripts, `conftest.py`, `.github/workflows/`, and `.gitea/workflows/` for untrusted execution hooks (and confirming no uncommitted local changes will be overwritten), check out the pull request branch:

```bash
gh pr checkout <id>
```

## Step 5: JSON Review Payload, Submission Modes & HTTP 422 Recovery

Write the review JSON payload to a temporary file (`/tmp/review-payload.json`) so Markdown code blocks and quotes never break shell escaping:

```json
{
  "commit_id": "<headRefOid>",
  "body": "Overall architecture is clean, but outbound RPC calls need bounded timeouts before merge.\n\n- 🚨 **Key Blocker**: Missing timeout on payment client (`src/clients/payment.py`)\n- **Inline Comments**: 1 🚨 Blocker, 2 💡 Tactical Suggestions, 1 🧹 Nit\n- ✅ **Positive Highlight**: `OrderAggregate` keeps retry idempotency isolated from transport concerns.\n\n### Verification Status\n- Tests: Passing (`pytest`)\n- Lint: Clean (`ruff check .`)\n\n*Generated by <agent harness> using model <model>*",
  "comments": [
    {
      "path": "src/clients/payment.py",
      "line": 42,
      "side": "RIGHT",
      "body": "🚨 **Blocker (Must-Fix)**: Remote network calls must specify an explicit, bounded deadline.\n\n**Principle**: Scale 1: Macro Resilience / Explicit Timeouts\n\n```python\n# Suggested fix:\nresponse = self.http_client.post(url, json=payload, timeout=5.0)\n```"
    }
  ]
}
```

- **Deterministic Commit Binding**: Set `"commit_id"` to `<headRefOid>` (from `gh pr view <id> --json headRefOid -q .headRefOid`) at the top level of the payload so inline comments bind to the exact commit reviewed.
- **Multi-Line Comment Spans**: For findings spanning multiple contiguous lines inside one diff hunk, include `"start_line"` and `"start_side"` alongside `"line"` and `"side"` (for example, `"start_line": 40, "start_side": "RIGHT", "line": 45, "side": "RIGHT"`).

### Submission Modes

- **Mode A: Pending Review (Default & Recommended)**:
  Omit the `"event"` key from `/tmp/review-payload.json` and run:
  ```bash
  gh api repos/{owner}/{repo}/pulls/<pr>/reviews \
    --method POST \
    --input /tmp/review-payload.json
  ```
  `gh` substitutes `{owner}` and `{repo}` from the resolved target repository. This call stages a **Pending** review on GitHub. Present the drafted summary to the user with the review URL `https://github.com/{owner}/{repo}/pull/<pr>/files` and instruct them to click **Finish your review** to inspect inline comments, edit, and publish.

- **Mode B: Autonomous / Published Submission**:
  When the user explicitly instructs direct publication without staging, add `"event"` (`"REQUEST_CHANGES"`, `"COMMENT"`, or `"APPROVE"` per the `Strict Approval Gate` in [SKILL.md](../SKILL.md)) to `/tmp/review-payload.json` and run:
  ```bash
  gh api repos/{owner}/{repo}/pulls/<pr>/reviews \
    --method POST \
    --input /tmp/review-payload.json
  ```

### Handling HTTP 422 Outside-Diff Errors

- If GitHub returns HTTP 422 (`Line could not be resolved` or `pull request review thread position is invalid`), an inline comment targeted a line outside the diff hunk.
- Do not guess line numbers or submit probe reviews to GitHub.
- Remove the rejected entry from `comments[]`, append it under `### Comments on Lines Outside Diff` inside `body` (creating that section if absent), and re-run the `gh api` call.
